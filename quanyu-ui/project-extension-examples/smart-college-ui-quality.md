# 智院项目扩展接法示例

此文件演示共享方法如何读取项目来源，不是第二份智院规范，也不改变当前发现入口。在项目决定采用共享插件时，由原项目维护者在原入口中接线；不向所有项目广播或强制迁移。

## 原入口保持唯一

智院原项目规则仍指向 `.agents/skills/smart-college-ui-quality/SKILL.md`，规范索引仍为 `docs/product/ui-foundation/README.md`。共享插件可用时，原项目技能只需说明本项目的来源和约束；不要再复制三份共享技能正文。可采用以下引用片段，不必新建扩展注册表：

```markdown
项目 UI 规范维护、视觉方案与实际复核使用已采用版本的
quanyu-ui:ui-standards、quanyu-ui:ui-design、quanyu-ui:ui-review。
当前任务只加载适用技能及按需细则，不强制每次三份全部执行。

先读本项目 AGENTS 和 docs/product/ui-foundation/README.md。
实施/复核仍执行项目 task-rules 的 UI 上下文，具体命令沿当前 AGENTS。
先从原领域合同确定用户应看懂和完成什么；核当前实际消费者及所评模式的必要信息、数据口径、下一步和返回。字段、状态、权限和业务操作按该合同保留，映射或组件采用不作为功能完成。只核本次变化，未变业务证据复用，不另建采用报告。
```

插件尚未安装/不可发现时，沿原项目技能和规范继续已授权工作，登记该工具层未核，不等待安装或虚称已消费。显式路径仍可读；不编辑分发缓存、重启在途会话或建立竞争副本。

## 只有项目能决定的内容

| 专属项 | 原来源/接法 |
| --- | --- |
| 专业蓝、思源黑体、标题/副文字的实际尺度、无页面副标题、标题旁帮助入口 | 原视觉基线、字体/标题/页面执行规范；共享方法只解释层级和帮助应服务任务 |
| 数值和样式运行来源 | 原版本化默认方案及 CSS 管理规范；不在共享技能写第二份 Token/预设值 |
| 跨应用原语与本项目组合 | Quanyu canonical `packages/design-system`、智院精确镜像和 `design-business`；共享技能不普遍要求其他项目采用这些目录 |
| 列表、详情、编辑与浮层实际 API | 原模式规范和真实组件接口；不从通用示意代码推断项目 API |
| L0/L1/L2、原型确认、证据声明和既有质量检查 | 原采用清单、原型/视觉验收规范及 task-rules；共享技能不把这些级别/审批推广为通用要求 |
| 业务路由、字段、IAM/File/Seed、TC/M/SRL 与验证身份 | 原领域合同、测试手册及用例；不放进 quanyu-ui |
| 本机预览、Git 单写、RM 安装、实际业务和用户验收 | 原交付/运行规则与原 round；不由插件新增发布门禁 |

## 一次任务如何消费

- 修主副文字：加载共享 `ui-design` 对应文字条目，再沿项目索引读取语义配对和真实 `ItemText`/字段组件接入。具体字号与品牌沿项目值。
- 评审长弹窗：加载 `ui-review` 长内容/返回细则，沿项目弹窗分区规范操作实际 Header/Content/Footer 与关闭规则；不为评审重新执行未变业务写入。
- 沉淀共性缺陷：加载 `ui-standards`，先判断是既有规范没执行还是缺口。正反例/接法入原规范；本次对象、提交和失败图入原 round。

如果未来其他项目采用，保留上述“方法→自己的索引→自己的组件与规则”的关系，替换项目专属来源，而非复制智院品牌与业务。没有专属扩展的项目可先引用其已有设计/组件文档，仅对当前任务缺项做有界说明；不要求先建设一整套规范才允许开发。
