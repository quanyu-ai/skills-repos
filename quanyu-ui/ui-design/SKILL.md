# UI 视觉设计

读当前项目规则、设计索引、适用模式、已确认参考和组件文档。保留用户选定方向，先区分探索、定稿实现和局部精修。项目扩展可以是其现有文档或专属技能；没有扩展时依据当前产品、目标端和可用设计系统提出有界假设，不继承其他项目主题、字体、组件名或审批规则。

## 选择或沿用设计语言

项目已选语言时沿其设计基线执行；用户要求比较风格或缺少视觉方向时，按需读取[可选设计语言](references/design-languages/index.md)，再只加载所选语言。提供沉稳商务、科技纵深、浅色空间，以及光场空间、电影柔光、银蓝精工三种空间扩展；它们不是自动换肤器，不覆盖项目Token、组件、业务或验收依据。三种空间扩展含关键词、来源、CSS角色、布局与离线效果示例；涉及导航/主辅区/窄屏组织时按需读[工作区结构](references/design-languages/workspace-layouts.md)。先将所选语言映射到项目，再制作代表工作面，避免只换颜色却改变状态或操作。

## 选择导航模式

涉及导航增长、宽窄承载、职责空间/域/功能、搜索与快捷入口时，按需读取[可选导航模式](references/navigation-patterns/index.md)。分组侧栏/抽屉与职责空间是不同适用条件下的选择，不强制把小系统改成三级，也不把成熟空间模型扁平化。沿项目真实可见目录与业务归属接入；颜色风格独立选择。

## 从任务建立视觉结构

确认页面面向谁、处理什么对象、当前状态、主要动作、真实信息来源和必须保留的条件。先确定主工作区及辅助区域，再安排卡片、表格和图表；不为填屏生成指标、虚构数据或修改业务含义。

识别现有基础组件、业务组合与实际 CSS/主题来源。优先用其语义角色，不在页面复制共享控件、另建默认值或修饰一处而全局改变组件。共享能力确有缺口时交其维护源；项目没有共享库时在原技术结构内做满足任务的最小实现，不先造整套设计系统。

按受影响任务读取 [视觉组织示例](references/visual-patterns.md)：文字与信息层级、列表/编辑/详情、表面深度、视觉精度和动效。规则中的角色是方法，具体数值、风格、断点和组件接口由项目决定。

目录、模板库或集成清单涉及持续扫描、说明维护和配置入口时，读取[目录工作面](references/catalog-workspaces.md)，处理密度、就绪分组、持久说明与上下文操作；不将其具体结构强制用于所有列表。

## 做出可判断的方案

用实际信息量、长短值和相关状态设计，不以空卡片、占位图或只有理想样本证明效果。宽窄布局按用户任务调整顺序和主次，不只机械改单列。需要参考产品时说明借鉴的关系和适配理由；不照搬品牌、业务、素材或未经核实的交互。

新交互或实质改变的流程，应表达正常路径、关键异常和返回上下文。项目已有 `prototype-design` 时复用其交互工作；没有时在本次方案中明确角色、入口、动作、结果和待定项即可，不要求为本技能安装另一插件。重大方向按现有项目/用户决定办理，普通精修不重新逐项求批。

已选视觉方向落地、共享基础推广或样例与产品差距明显时，按需用[实现质量控制](../ui-review/references/implementation-quality.md)核真实内容、角色接入、设计偏差与功能/视觉双结论；工具只拦可判定缺证，不代替实际视觉判断。

## 连续调整与交付

先在本机可操作方案或真实组件及实际样式中看整体和关键局部，优先解决首屏任务、主次、扫描效率、操作发现和状态表达，再做光学对齐、表面和动效。静态图只能评静态内容；方案完成不等实现、真实业务或用户接受通过。

需要从已确认基线实现或检查还原时，已有 `design-implementation-fidelity` 可复用；缺少该技能也须保留基线版本、设计到组件/状态映射及受影响对照，不自行重设计替代基线。

在原记录给出可查看入口或产物、采用依据、组件与状态范围、待决项和未验证边界。复用未变证据；仅提出需用户决定的真实取舍并集中汇总，不把视觉迭代变成发布或全站审计前置条件。
