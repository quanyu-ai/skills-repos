# 可选设计语言

这是跨项目的视觉组织参考，不是主题安装器、组件库或项目默认配置。项目已确认的品牌、组件、设计基线和用户决定优先；不因插件升级给已有系统换肤。没有选择时，结合用户目标提出推荐并说明取舍，普通修复沿原风格执行。

| 名称 | 主要关系 | 适合优先探索 |
| --- | --- | --- |

只读取选中的语言文件；比较多稿时按比较范围读取。它们不是互斥的业务模型，也不分别授权操作。A/B/C等编号属于具体项目；先查该项目映射，不根据字母推断含义。选定一种语言后，可有紧凑/常规密度，但不要在相邻模块任意混用不同材质体系。

接入时将颜色、字体角色、间距、圆角、表面和动效映射到项目已有Token/组件；已有值不一致时记录有依据的适配，不复制一整套并行状态或权限规则。文件中的色彩起步示意仅帮助讨论，不能覆盖项目已验证值。Figma和代码分别实现同一语义角色；插件不承诺自动同步，也不强制使用Figma。

在原任务中记录：所选语言及依据 → Token/组件映射和允许材质区域 → 本批页面/状态/视口及密度 → 实际视觉和受影响行为证据。根据本批范围检查密集列表、复杂表单和异常状态；首次扩大覆盖时优先补缺失代表场景，不为维护规范重跑未变业务。

页面完成、独立复核与用户接受分别报告。单个好看的详情或成功态不代表设计语言已经适配全平台。字体、透明度和平台限制需要真实观察；尚无样本的状态明确未验，不生成业务记录或假状态求通过。
