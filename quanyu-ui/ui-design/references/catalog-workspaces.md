# 目录与模板库：连续扫描、说明与配置

适用于能力/流程目录、模板库、集成清单等需要持续寻找、比较和维护条目的工作面。它补充 visual-patterns，不规定所有项目采用某种主题、表格、三级导航或固定像素。项目已有组件、状态、目录和持久化契约优先。

## 先区分用户要找什么

目录条目先回答“做什么、需要什么、得到什么、何时适用”，状态/版本/来源/当前设置分开呈现。说明能展开不代表主列表已足够可理解；必读的使用限制或未就绪原因应在其影响的工作面就近可见。技术编号、摘要与原码供追溯，不能代替可读名称和业务说明。

名称和说明本身不准确时，先确定存储与维护权威。若来自真实目录，不在前端按ID硬编码漂亮介绍来伪装数据已整改；改正持久内容，并沿原契约维护其说明版本。视觉调整不授权改执行定义、部署绑定或历史快照。

## 密度与空间分别服务任务

**问题：** 页头、环境条、工作台口号、说明、页签和大卡片叠加；每条记录内再重复状态、版本和操作，少量内容也需不断滚动。材质统一后仍像放大的原型。

**做法：** 合并重复识别信息，保留清晰页头和主要入口；环境信息使用已有宿主位置，帮助放在对应工作面。列表内用对齐、分隔和较紧凑节奏支持连续扫描，面板之间用留白与深度区分范围。不能为了提高数量把正文缩小到难读，也不能将必读风险藏进帮助。

**结构正例（示意，不是接口）：**

```text
目录名称                              主要维护入口
[当前分类]  其他分类
[名称或说明查找]   [实际状态]   [查询]

条目名称 / 用途       目录状态       当前设置       上下文操作
定义版本             单独说明        可读配置名
                      按需展开：所需资料 / 交付内容 / 适用范围
                      高级：精确引用 / 技术血缘 / 原始检查码
```

对照多个字段时可用表格或稳定网格；需要读不同流程节点时可用紧凑记录。不要把每条都拆成等大孤立卡片，也不为填满空间添加没有数据来源的指标。

**观察：** 同一真实条目集、同一目标视口下比较首个工作项位置、主信息与操作是否可扫读、长说明是否挤走状态。不要仅以卡片数量或首屏条数宣布视觉通过；复杂任务允许不同节奏。

## 配置、版本和就绪不混在介绍里

- 当前分类需有清楚的选中态。页面链接用合适的当前页语义；只有实现了对应键盘行为才使用完整tab角色，不能为了造型加不成立的ARIA。
- 维护操作沿原条目和精确版本定位；从某能力进入配置应保留能力上下文，不将整库设置误写成该条配置。“新定义”和“编辑说明”按实际契约分别命名。
- 目录已登记、执行就绪、当前默认、本次调用成功是不同事实。状态颜色需要文字解释，不能把一个绿色标记泛化为全部可用。
- 草稿或待接入是正常建设状态，不必用执行失败的警报视觉。保留各自独立的缺口及下一责任；不能将“缺能力”和“执行器限制”合并成一个修好就能运行的承诺。重复的不可执行句子可合并，限制本身不能丢失。
- 流程概览可展示真实能力节点；只有依赖确为直线时才画单向链。分支、未供版本和缺配置按原数据表达，详细依赖与精确引用仍可展开。

## 窄屏承载与返回

窄屏先保名称、状态、关键说明和操作；可将列转为带标签的记录，不机械压缩全表或让整个页面横滚。展开长内容后仍能找到收起、返回及原对象；检索条件、分类与配置上下文沿既有路由/组件保持。输入、选择器与折叠入口维持项目触达标准。

共用导航需要压缩时，保留当前定位与可获取的完整路径。不要为某个目录的截图改动所有业务页；需要全局调整时另列共享调用点及验证范围。

## 设计覆盖与通过边界

请求详情的漂亮代表稿不能证明目录页已经设计完成。对本次受影响的列表、分类、筛选、空态、展开、编辑和返回提供准确映射；共享组件相同可复用，但任务和布局不同需看差额。

探索稿身份、样本来源及性质保留在内部评审记录或 manifest/delivery；正式采用节点使用真实业务内容或自然业务示例，并与代码状态、精确对象和视口对应，不将制作身份或合成标识写入产品UI。真实业务所需的来源、版本和必要告知仍准确保留。功能/数据有界通过、视觉自查、独立视觉复核、用户接受分别记录；功能通过不能自动升级为整体视觉达标。

检查允许与拒绝行为时只运行必要差额。纯展示/密度精修不应重放已成功业务；说明保存若变化，沿合法说明版本验证保存、刷新和冲突，不借此重跑执行任务。

共用说明编辑路由按实际目录集合保留菜单与面包屑归属，并验证取消返回；实现路径名称不应决定业务归属。执行限制提示必须适用于真实节点结构：零节点与多节点同受限时使用准确的通用条件，不凭限制码推断已有多节点。
