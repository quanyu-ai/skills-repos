# 职责空间 / Space–Domain Workspace

适用：已有稳定职责空间、多个域和大量功能的组织型系统。空间→域→菜单项是三层语义，不是三个外观层级。空间承载任务上下文；域组织相关功能；菜单项关联canonical functionId及Primary Home。真实空间导航链接和域分组不机械改为tablist/tree；链接当前态与查找范围按钮状态分别用适合的语义，不泛加aria-selected。页面标签、详情、步骤与状态不自动扩成第四级全局菜单。

这是可选模式及改进方法，不代表任何既有项目已经迁移或通过运行验收。项目已有三级和跨空间查找时，只改本批已识别差额，不重建框架。保留该项目自己的空间集合、目录权威和发布职责，不把示例名称或其他项目权限规则带入。

## 三层各自承担什么

- 空间层：仅显示当前上下文实际可进入的空间。宽度充足可用标签，收窄用明确空间选择器，不强制全部横排。切空间不授予角色/权限；系统管理等全局治理区按项目合同独立呈现。
- 域层：侧栏聚焦当前空间的业务域，当前域/功能稳定可见，其余已授权域可收敛但仍可发现。长名保留完整读取途径；折叠图标态仍需替代名称，不能只剩相似图标。
- 功能层：每功能一个Primary Home；面包屑、侧栏、空间当前态、搜索、常用和最近都引用同一功能ID。使用同一带路径段/合法查询条件的路由解析规则，不将相似前缀误作同一功能。

## 跨空间查找与返回

将“当前空间浏览”和“跨空间查找”分开表达。查找范围有准确选中语义和可读状态；选择全部范围本身不改变用户当前空间或权限。结果显示空间/域/功能全路径，选中后沿现有合格投影提供的canonical入口/Primary Home定位所属空间，不凭功能ID猜URL。功能查找与对象深链分开，保留必要路径/查询参数及返回上下文。若保留全空间浏览，标题明确“全部空间导航/功能总览”，不能混列后仍称当前空间导航。

常用/最近仅在项目已有或单独授权的能力下复用，不随模式自动新增偏好存储、接口或数据；只引用当前仍有效的功能，跨空间快捷标注归属。源不可用与授权拒绝分别表达，失效快捷不可补造入口。关闭查找/返回原功能时保留明确上下文，不让业务页面因菜单刷新重建。

## 目录与状态

沿项目现有合格目录投影及身份隔离机制，不要求另造前端权限框架。服务已有会话快照时，切空间、范围和搜索优先做同快照的本地投影；不从少请求次数推断首读延迟、SQL或一般性能改善。

保留加载、合法无项、部分来源不可用、刷新中、刷新失败仍显示上次内容及身份失效的区别。目录缓存不是业务ALLOW；业务API继续实时授权。偏好、菜单快照、业务行和凭据分别处理，不将共享浏览器localStorage当跨用户目录缓存。

## 宽窄布局与复核

先明确本项目移动承载是否采用模态契约；采用模态时沿既有Dialog/Sheet验证，不能仅因用了aside或未写字面inert判运行失败。此模式建议窄屏采用一个模态抽屉：先有明确空间选择器，再浏览当前空间的域与功能。不要把所有空间树同时摊开。搜索可以独立模态面板；两个模态的接续沿已有组件契约，避免叠层焦点混乱。

优先验证：图标按钮和折叠链接的名称；空间/搜索范围的ARIA当前态；当前/全部标题与实际范围一致；长功能名及路径；抽屉完整模态行为；刷新失败保留旧目录并说明；身份切换后旧菜单不泄漏。已有当前叶/aria-current已修复的版本不能继续引用旧缺陷要求重复整改。
