# 实际评审：证据与定位示例

只选择与当前修改有关的路径。示例中的位置关系可泛化，数值、设备、动作数与字段不是固定门槛。

## 1. 先看真实承载，别被测试表象误导

| 观察 | 合理判断 | 不能直接推断 |
| --- | --- | --- |
| 某标签定位不到，但页面显示控件 | 从实际可访问树/组件契约重新定位 | 组件无障碍必然失败或接口错误 |
| Dialog 包装根没有尺寸 | 检查实际面板、正文与遮罩 | 整个弹窗不可见 |
| 自动化输入失败 | 区分工具方法、原生输入和受控状态；用允许的正常方式核对 | 重写全局输入组件 |
| 新页到技术预览的未连接占位 | 记录该路由在此环境不可观察 | 正式产品路由已坏或已通过 |
| Screenshot/DOM 包含所需文字 | 继续看视口、遮挡和实际呈现 | 用户已能察觉或操作 |

若换工具或请求方式，不突破环境安全拒绝和原访问范围。只锁受影响验证，不为补证据绕过安全限制。

## 2. 分页与可见反馈

**复现例：** 在窄屏长列表切下一页。新数据已经更新，焦点也落在列表容器，但视口只显示新页末尾。

**判断方法：** 看范围提示和首条记录是否在视口内；必要时读它们的实际矩形。超长容器被聚焦时，浏览器的最近边缘定位未必让开头可见。焦点存在与目标可见分别核对。

**可接受修复：** 沿现有定位能力把新明细起点带入视野，保留原筛选、页码和范围；若用显式滚动，不把它变成无关全页首滚动或额外请求。具体实现按组件和平台约定，不规定所有产品都手动调用 scrollIntoView。

**定向复验：** 在原失败视口走同一分页，看提示、首条和数据范围；原来通过的计数、筛选和宽屏证据可复用。不要为了复验分页重复原数据写入。

同类情况包括保存按钮变禁用后焦点丢失、查询恢复按钮卸载后提示留在屏外。根据新状态选择原对象的合理后继控件或可见反馈，不机械聚焦任何带 ref 的大容器。

## 3. 长内容、嵌套确认和返回

**复核路径：** 从列表后部打开原对象详情/编辑；看标题和摘要；实际滚到长正文末尾；打开必要的脏值确认；选择继续编辑或明确放弃；关闭后查看原对象、条件、滚动与焦点。

**正例：** 长内容可完整读到，关闭与任务动作可达；继续编辑保留稿并回可见输入；放弃才清除；若原触发器因状态变化被禁用/移除，返回合理的现有后继位置。

**反例：** 用一张 fullPage 图证明正文已读到底；只验取消而遗漏 Escape/X；把 disabled 改成可点方便测试；关闭后焦点落页面根，却只因没有报错判通过。

**边界：** 嵌套确认和 dirty 状态属于本次改变时才补。实际保存没改时引用有效读回；如果打开就会生成草稿或产生其他副作用，先明确原业务行为与授权，不当作无副作用浏览。

## 4. 宽度与表面不能只看代码

**复现例：** 双列表单的窄屏选择器溢出，开发已加 min-width:0，但仍显示裁切。

**定位：** 检查真实正文、字段容器和控件各自的尺寸与计算样式。fieldset/网格子项的最小内容尺寸、控件本身显示模式或未编译的工具类可能各自限制宽度；先定位，不连续堆覆盖类。

**正例：** 修真正约束后，同目标视口重新展开原选择器，长值可读、操作可达，浮层不被父容器截断，页面不意外横滚。

**反例：** 只看类名含 responsive 就通过；为塞下长值缩小全局字体；控件单独预览正常就忽略实际父容器；已有规范允许的内部表格横滚一律判错。

同样查看背景/主表面/浮层真实关系。没有阴影不必然失败，有阴影也不证明层次正确；判定落到本项目设计和任务可读性，不列一个跨项目统一“立体感分数”。

## 5. 状态与证据边界

**正确区分：** 未选对象、尚未读取、来源失败、拒绝、成功为空、缺少某字段、结果未知与成功。局部失败保留作用范围，不能为了简洁把未知改成零或清空其他已知事实。

**正例：** 使用明确标注的合成样本检查空态、长值、未知反馈；结论只写本机组件表现。实际角色、授权读取、写入持久化和安装仍沿项目既有验证单独说明。

**反例：** 看到 HTTP200、模拟成功、已显示某按钮就签真实业务通过；以无可用样本为理由制造权限/业务记录；规范更新后倒补重跑已通过业务。

## 6. 原记录里的最小发现

```text
对象：本次候选版本；目标入口与视口；实际/合成样本
动作：从哪个可见入口做什么
观察：具体哪里不可读、不可见、误导或上下文丢失
依据与影响：项目哪条设计/任务要求；影响谁完成什么
分类与责任：功能 / 规范 / 共享能力 / 审美建议 / 待决定 / 未运行
修复与复验：后继版本；同路径观察；复用何种有效证据
剩余：没看过什么、为何、原负责人；不把它升级成通过
```

使用已有任务记录即可，不强制这些字段变成新 JSON schema、审批表或额外工具门禁。

## 7. 打开态浮层、样式顺序与退场命中

**问题：** 帮助面板在缩放窗口后被裁切；基础组件和业务组合同时覆盖 transform，预览加载顺序正常而完整样式下偏移；关闭动画保留透明节点，立即点击后方按钮仍被拦截。

**正确定位：** 检查稳定打开态的实际边界和最终生效样式，而非只看关闭后的按钮或可访问树全文。定位与边界修正应由实际负责浮层/组合的组件统一处理；属性所有权发生冲突时修组合，不逐业务页堆高优先级。复现了样式顺序差异才保留对应有限回归，不要求所有页面枚举全部加载顺序。

**正例：** 浮层打开时调整到受影响目标尺寸，内容及关闭入口仍可读；关闭后立即按正常指针方式触发后方原动作，逻辑关闭的浮层不再吞掉点击，退场视觉可以继续。已有焦点和关闭语义保持。

**反例：** 只调 opacity 就视为无命中；测试先等待固定时长，或使用自动等待可点击的操作掩盖透明遮挡；仅因 AX 有全文、最终截图正常就签定位通过。

**通过条件：** 对本次实际影响的打开/缩放/关闭状态分别观察可见性和必要的指针命中。只读页面可使用原无副作用动作验证；有副作用的后方操作不能为取证擅自触发。组件模拟结果不自动覆盖真实安装后的消费者。
