# 实际界面复核

读取当前项目规则、设计索引、采用基线、任务范围和已有证据。项目专属扩展、工具、访问方式和原责任分工优先；没有扩展时以当前需求、已确认设计和可用组件契约为依据，只补本任务缺项，不借用其他项目风格或授权。

使用可选语言时，按项目记录读取[语言入口](../ui-design/references/design-languages/index.md)及所选文件，将其材质/密度约束纳入受影响检查；未选语言的页面沿原基线，不因插件更新批量重审或改风格。

## 定义可观察范围

绑定实际候选、入口、目标视口、对象/状态和样本性质。沿可见动作识别受影响列表、子页、详情、编辑、帮助、菜单、选择器和确认框。主入口通过不代表其下全部表面通过；同组件同版同态可复用，入口、对象或返回上下文改变时检查对应差额。

先用已有有效证据，比较输入是否仍一致。缺入口、合法样本、权限或来源的分支写明未运行及最小缺件；不能标通过，也不因此停止可独立完成的表面。审计/只读任务不直接整改，整改任务在授权范围内修复；不要为截图执行未经授权的业务写入。

## 实际看和操作

选用当前环境允许的浏览器/原生工具和已有脚本；技能不指定必须安装某种工具。先看完整工作面，再看关键局部，按项目目标端查看相关宽窄布局。对层级、字体、间距、列宽、表面/浮层和首屏任务给具体观察，不以导入组件、规则勾选、DOM 文本或截图文件存在代替观看。

按本次影响实际打开/关闭浮层、读长内容顶部与底部、检查必要的键盘与可见焦点、钻取及返回。可用时用可见矩形和滚动尺寸说明裁切或屏外位置，但测量不能替代观感判断。相关正反例与排错见 [评审操作示例](references/review-examples.md)。

## 分类、修复、复验

区分影响任务正确完成的功能问题、规范未执行/缺口、共享组件问题、视觉质量建议，以及待业务决定或无法观察。审美偏好不冒充规范违例；共享组件默认正确也不证明页面组合合格。按用户影响定优先级，交实际维护者修，不因评审自动接管业务页面。

对授权整改保留原失败，绑定后继候选，只复验受影响路径与共享消费者差额。未知写入先沿原恢复路径查明，不重发或改授权求通过。未变的业务/安装证据继续有效；不为凑覆盖数重跑全模块。

## 如实交付

在项目原问题单、round、PR 或交付记录写入口/动作/观察、源版本、证据、影响、责任者、后继与剩余项；不自动创建另一台账。源码/结构检查、本机模拟、真实授权业务、目标环境安装和用户接受分别给结论，有限通过只覆盖已看过的版与态。

有 `prototype-review` 时，交互原型的角色与业务路径复用它；无该技能也须在当前界面走清本次入口、动作、结果与返回，不虚称独立评审或强制安装。设计还原检查有既有技能时复用；不重复其整套流程。全部必改项在本批范围达成就交付，非阻断建议与缺样本项单列，不把验证本身延展成主线。
