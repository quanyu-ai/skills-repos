# 结构化设计体系与当前有效基线

用于多稿探索、共享组件推广、样例到实页出现落差或现役规范互相冲突时。普通局部修复沿项目已有结构执行，不为每次修改建立新系统。以下字段是可适配的记录合同，不是目标项目API、主题注入器或强制文件命名。

## 从语言到证据的链路

业务需求/状态 → 十维设计语言 → 稳定语义 → 组件合同 → 页面组合 → 实际功能/视觉观察 → 有界基线升级。业务事实和权限不属于视觉配置；语言配置不能凭空开启能力或改写状态。

先找项目现役入口。已有同类数据或schema就扩展其最小缺项；没有时可以用一份结构文件作为组织源，生成可读视图。当前源、生成视图、实现源和采用设计的职责要写清：文档不会让未接入的消费者自动采用。原始token只保留一处数值源，引用/读取它，不多处手抄。

历史报告与参数快照归档保留原摘要，现役入口仅列有效项和兼容跳转；不要更新旧manifest去伪造它当时已符合新基线。旧报告的SHA可通过归档原字节核对。

## 十维框架

| 维度 | 应表达的关系 |
| --- | --- |
| 任务与信息组织 | 对象、事实、下一步，导航/任务/结果层级 |
| 布局与空间 | 主辅比例、对齐、密度、留白和阅读节奏 |
| 文字与排版 | 字号/字重/行高、长值、缩放与多语言 |
| 色彩与语义 | 冷暖、多色克制、强调与状态含义/对比 |
| 表面与空间层次 | 背景、普通/上下文/重点卡的材质、边缘、投影和光源 |
| 组件与图形形态 | 尺寸、圆角、图标、变体与焦点 |
| 交互与状态反馈 | 加载/空/错误/禁用/进行/完成和恢复 |
| 响应式与可访问性 | 顺序、抽屉、键盘、命中区、焦点与减少动态效果 |
| 动效与时间节奏 | 反馈及时、过渡帮助理解、不阻塞或干扰 |
| 内容与数据表达 | 文案、单位、日期、版本、来源和真实状态 |

每维五项至少齐全：目标、实现角色、正反例、适用场景、可观察通过条件。视觉层级由多维共同建立，组件一致性贯穿全部；不要把“空间感”“高级”单独写成无法验证的分数。

示意记录（参数和编号由项目决定）：

```json
{
  "id": "surface-depth",
  "goal": "形成可辨主次且保持可读",
  "implementationRoles": ["surface.task", "surface.context", "surface.focus"],
  "applicableScenarios": ["对象详情", "长表单"],
  "positiveExample": "普通卡有弱材质，上下文更淡，重点卡更突出",
  "negativeExample": "普通卡全变纯白，或每卡都使用同强度彩色光晕",
  "criteria": [{
    "id": "surface-depth-1",
    "observable": "宽窄实际卡面都能辨认层次，正文清楚，主动作仍突出",
    "method": "actual-observation",
    "evidence": "同对象/状态/视口的配对图与实际观察"
  }]
}
```

## 设计语言包

至少包含id/version/status、逐维方向、稳定角色的覆盖、来源/参考与可查看效果、组件/布局适配范围、状态证据、升级条件。共享框架不等于各语言只剩颜色不同。

[语言库](../../ui-design/references/design-languages/index.md)保留沉稳商务、光场空间、电影柔光、银蓝精工等独立起点。项目A/E/F等编号须显式映射名称，不跨项目猜字母。被保留的基础效果持续完善，状态可以是参考/候选/有界采用/被替代；不因当前只采用一种就删除其他已积累的效果。不把插件示例状态当真实项目全站已适配。

## 可替换语义

| 字段 | 含义 |
| --- | --- |
| id/name/kind | 稳定用途、可读名称与类型，避免蓝卡/第三块等具体外观命名 |
| source或alias | 唯一值源/引用；别名须无循环，来源缺失不能猜 |
| dimensions | 该角色影响哪些维度 |
| replaceable/constraints | 哪些层允许替换，最小可读/触达约束等保护边界 |
| language.semanticOverrides | 覆盖角色，未覆盖继承共同基础；未知角色拒绝 |
| runtimeScope/readiness | 解析、组件消费、运行覆盖、全部状态与接受分别记录 |

共同基础 → 语言 → 项目允许的上下文覆盖，层级依项目权威决定；不要为动态换肤新增租户权限模型。撤销从父层重算或恢复仍由自己拥有的值，避免覆盖别的预览/进程更新。业务含义不放进皮肤。类型、别名、缺失、保护边界可脚本检查；颜色对比、布局和字体最终效果另行观察。

一个源有token、样式管理有API、组件有TS类型或数据库有schema，均不等于整条设计体系已执行。逐层记录定义→映射→消费→运行覆盖/撤销；无运行注入时明确“离线解析/参考”，不能宣传成全站主题切换。

## 组件合同

组件记录目标、语义角色、结构槽位、变体、状态、不变量和实际实现入口。页面配方记录主辅顺序/密度/窄屏承载，业务流程另由项目需求决定。修复实际共享入口，保留调用兼容；无明确需要时不另造框架。

比如Surface合同需区分任务、上下文、焦点；Button需区分普通、主动作、焦点表面动作、禁用/处理中；表单还要覆盖错误和恢复焦点。状态清单是覆盖要求，不代表都已通过。组件默认正确不证明组合页面正确，长文、嵌套表面、浮层和窄屏仍需实际核对。

## 工具、比较与执行约束

Figma用于探索/组件库/采用目标/跨页评审；代码适合真实内容、共享接入与局部修复。不强制整页重生成。记录concept/candidate/adopted/superseded、文件/节点、目标版本、视口与缺项；采用前核业务字段/状态/动作，采用后绑定节点→组件槽位/角色→源文件→实页证据。若调用Figma工具，加载相应工具技能。生成图不是实现图；截图导入不是双向同步。

固定同对象/内容/状态/视口/缩放/字体就绪/滚动位置，分别核结构语义、渲染、交互。并排/叠加/像素差用于找差异，不能作为美观评分；对比来源/目标或源码变更需失效对应证据。已批准的差异先记录理由再升级目标，不用代码结果静默重定义设计。

每批绑定基线path/hash/version/language，记录变更角色、组件和影响维度；角色依赖自动展开。维度证据可为实际观察、依据充分的未变复用或明确不适用；首次语言/外壳推广覆盖代表目录/详情/复杂表单及宽窄和关键异常，局部修改只重验受影响范围。新批次入口应拒绝漏基线，历史记录保留原格式，避免用兼容旧记录的入口绕过新要求。

UI负责人维护语言/角色与采用目标；实现者维护共享消费与自检；独立复核者分别给功能/视觉结论；协调者维护原索引；用户接受单列。用项目已有测试/命令检查结构、来源、版本、缺证及必改未闭；实际观看审查材质/比例/主次。无现成脚本时先定向人工执行，不为了采用本文另造审计平台。

“稳定/确定性”指映射可重算、版本可定位、差异可追踪、证据可复查，不承诺跨设备逐像素一致或审美自动判定。规范、代码、安装、可发现、实际使用和用户接受分别给结论。
