# 单人作业模式

## 适用场景

一个 AI 独立负责一个项目的开发，直接接收上级指令，自己拆解执行。

## 工作流程

```
接收指令 → 分析任务 → 拆解为步骤 → 逐步执行 → 验证 → 记录 → 汇报
```

## 自我管理规则

### 任务拆解
- 文案、外观等不改变业务规则的调整直接做受影响的检查。新功能或跨组件变更按可独立验证的业务结果拆分，引用需求和方案，记录负责方、实际影响面、依赖和检查。
- 权限、金额、状态、真实外部操作等边界若有未决规则，明确哪一行为受阻；可继续有确定依据的设计、原型或隔离测试。没有明确的技术文件时先写清接口和业务验收，选定实现后再补具体路径。

多步变更按 `implementation-planning` 拆分。遇异常或关键行为回归时，按需使用 `engineering-debugging` 或 `regression-testing`。

### 代码提交
- 按项目约定组织有意义的变更和提交，推送、发布及通知按现有授权执行。

### 验证与记录
- 按 `delivery-verification` 读回可归属于当前版本的验证结果。已有证据与当前条件匹配时可复用，变更后复核受影响范围。
- 适用时分别记录源码验证、安装版本读回、实际业务验证和 Owner 接受；缺证据时注明未执行、未通过或待确认。沿用项目既有记录位置。

### 汇报
- 任务完成后向上级（创始人）汇报结果
- 遇到阻塞问题及时汇报，不要卡住不说

## 与团队协作

- 执行项目已采用的共用规范。按风险安排评审，本地差异也可评审。

## 原则

- 独立不等于随意，共用规范必须遵守
- 不确定的事先问上级
- 做完的事要有记录，不能只在脑子里
