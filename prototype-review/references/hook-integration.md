# 用 hook 触发原型交接检查

技能规定评审动作、证据和结论。Hook 可在项目已有交接入口提醒或运行确定性检查，复用同一评审流程。

| 触发点 | 适合自动检查 |
| --- | --- |
| 标记实质交互变更可交接 | 原型入口、需求引用和当前评审记录是否存在；评审记录的原型版本是否与候选匹配。 |
| 评审发现影响交接的问题 | 原交付记录是否保留受影响切片、问题和复验状态。业务意义由评审流程判断。 |
| 普通文案或样式变更 | 若需求、任务、权限、状态和信息含义未变，只提示受影响画面检查。 |

按项目已经具备的入口接入，例如原型发布命令、交接检查或已有 CI。针对一个原型版本与交接事件运行一次，记录结果。评审记录缺失、版本变了或检查工具不可用时，指出具体缺口；项目未接入 hook 时，从原交接动作直接运行技能。先用提示模式核对正常、缺证据和轻量场景，只有项目确需且有可靠判断依据时，才将明确可判定的检查作为交接条件。

Codex 生命周期与 OpenClaw 插件事件各有自己的配置、匹配和信任机制。适配代码放在选用它的项目或插件中。选择能对应原型交接的事件，避免在每次编辑、工具调用或普通会话结束时触发全面评审。
