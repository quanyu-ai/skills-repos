# 行为与回归测试

从用户能观察到的行为或稳定业务接口写预期。选择能捕捉目标缺陷的最小测试层。权限应覆盖真实授权边界，数据一致性应覆盖实际写入边界。使用隔离数据与项目已有测试工具，明确替身覆盖的范围。

1. 对可复现缺陷和适合先写测试的关键行为，先在未修基线上运行定向测试。核对它是否因预期业务断言失败。测试未启动、样本无效或环境错误先单独处理。
2. 修改最小必要实现后，运行同一测试并读回结果。必要时补主路径与关键拒绝或恢复场景，运行受影响的现有测试。重构时用既有行为基线做前后比较。
3. 已有实现时，可在安全的隔离基线上验证同一断言能抓住旧行为。基线无法复现时，记录原因、当前检查的覆盖范围及尚缺证据。涉及有副作用的操作使用可控测试数据。
4. 保留测试位置或操作步骤、适用版本、输入和实际结果。优先断言可观察结果，避免把断言绑在可替换的内部实现上。

已有用例能捕捉该回归时复用。低影响改动使用与影响相称的检查。
