# skill-template - req-trigger 设计说明

## 为什么需要这个 skill

当前问题：
- 龙哥哥说"智策首页404"，AI如何确定这是需求？
- AI如何识别项目（智策/晨曦/智院）？
- AI如何判断是bug还是新功能？
- 需求如何准确转化为REQ条目？

这个 skill 提供明确的**触发方式** + **自动识别规则** + **确认机制**。

---

## 触发方式（3种）

### 方式1：斜杠命令（推荐）
```
/req 智策首页404修复
/req [-p P0] 智策登录功能必须修复
```

### 方式2：JSON格式
```
{"project":"smartops","title":"首页404修复","type":"bug","priority":"P1"}
```

### 方式3：固定前缀
```
[REQ] 智策首页404修复
[BUG] 智策订单加载慢
[FEEDBACK] 智策商品搜索功能需要
```

---

## 自动识别规则

### 1. 项目识别（关键词匹配）
```
"智策" → smartops
"晨曦" → chenxi-study
"智院" → smart-college
"权舆" → quanyu-console
"智签" → contract-platform
```

### 2. 类型识别（关键词匹配）
```
"bug/error/错误/问题/故障" → type=bug
"需要/想要/希望/功能" → type=function
"优化/改进/调整/改善" → type=optimization
```

### 3. 优先级识别
```
默认：P1
龙指定：/req [-p P0] 描述
P0 = 必须立即修复
P1 = 重要，尽快处理
P2 = 次要，可延后
```

---

## 确认机制

AI生成REQ草案后，**必须等待用户确认**：

```
✅ 已识别需求：
- 项目：智策 (smartops)
- 标题：首页404修复
- 类型：bug
- 优先级：P1

我来创建 REQ-20260525-004.md
输入 /approve 确认创建
或 /edit 修改描述
或 /cancel 取消
```

用户回复：
- `/approve` → 创建REQ
- `/edit` → 修改后创建
- `/cancel` → 取消

## 与 requirement skill 的关系

## 实际例子

### 场景1：基础需求
```
龙哥哥：/req 智策首页404修复
→ AI：生成 REQ-20260525-004 草案，等待确认
龙哥哥：/approve
→ AI：执行 requirement/new-req.sh，创建REQ
→ 返回：✓ REQ-20260525-004 创建成功
```

### 场景2：带优先级
```
龙哥哥：/req [-p P0] 智策登录功能必须修复
→ AI：生成 P0 优先级草案，等待确认
龙哥哥：/approve
→ AI：创建 REQ-20260525-004 (priority=P0)
```

### 场景3：项目明确
```
龙哥哥：/req 项目：晨曦学园 课程表显示错误
→ AI：识别 project=chenxi-study
→ AI：生成 REQ-20260525-005 草案，等待确认
```

### 场景4：取消
```
龙哥哥：/req 智策首页404修复
→ AI：生成草案，等待确认
龙哥哥：/cancel
→ AI：已取消
```

### 场景5：编辑后创建
```
龙哥哥：/req 智策首页404修复
→ AI：生成草案
龙哥哥：/edit 首页返回404错误，用户无法访问
→ AI：用新描述重新生成草案
龙哥哥：/approve
→ AI：创建 REQ-20260525-004
```

## 错误处理

### 情况1：识别失败
```
龙哥哥：/req 首页有问题
→ AI：未识别到项目，请说清楚是哪个项目
```

### 情况2：表述模糊
```
龙哥哥：/req 智策有问题
→ AI：识别到项目是智策，但需求描述太模糊，请具体说明
```

### 情况3：需要更多信息
```
龙哥哥：/req 智策订单慢
→ AI：已识别"订单响应慢"需求，但需要确认：
  - 是哪个页面？/orders 还是 /order/[id]？
  - 具体表现？首屏慢还是整个页面加载慢？
  - 期望阈值？<500ms 还是 <2s？
```

---

## 安全机制

1. **必须确认**：任何REQ创建前必须等待用户`/approve`
2. **禁止自动覆盖**：不允许覆盖已存在的REQ
3. **项目隔离**：A项目的需求不能写入B项目目录
4. **回滚能力**：确认前可以随时/cancel

---

## Phase 路线

- **Phase 1（当前）**：3种触发方式 + 关键词识别 + 确认机制
- **Phase 2**：自动提取标题/描述/优先级（NLP）
- **Phase 3**：与 requirement skill 自动联动
- **Phase 4**：跨项目需求对比+去重
