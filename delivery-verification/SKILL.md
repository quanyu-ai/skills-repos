# 交付核验

先确定本次要证明的结论和适用范围。从需求、实施记录或缺陷回执选出受影响的验收行为。对每项核对证据来源和对象，记录通过、失败、未执行或待确认，并注明后续负责人。

| 要证明的事项 | 核对的证据 |
| --- | --- |
| 源码变更通过检查 | 实际变更的版本或差异、适用检查和已读回的结果。 |
| 候选已安装 | 目标环境独立读回的运行版本、受影响配置与必要保留项。 |
| 实际业务行为通过 | 正常入口、实际角色、对象、操作与结果。按影响覆盖必要的拒绝或异常路径。 |
| 业务方已接受 | 有权验收人的确认或项目约定的原始验收记录。 |

证据仍对应当前版本与适用条件时可复用。变化涉及版本、配置、角色或数据时，重验受影响部分。健康检查证明服务可达，业务声明需对应业务证据。模拟验证保留模拟范围。

同一记录累积多轮结果时，给出当前适用的摘要，并标明旧失败或未执行结论的版本及后继证据，保留原始历史。分别核对文件已安装、平台清单可发现、入口实际加载和行为验证；其中任一项不能替代其余项。清单漏列而文件可读时，只按当前证据记录发现缺口，不推断为技能逻辑错误或用文件改动冒充平台恢复。

合并、发布和交接沿项目现有入口执行。发布前确认候选、实际写入范围、回退条件和复验责任方。遇到未知写入结果时先走原读回路径。收尾更新原任务或交付记录，给出已证实结果、剩余缺口和下一可行动节点。
