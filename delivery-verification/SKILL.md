# 交付核验

先确定本次要证明的结论和适用范围。从需求、实施记录或缺陷回执选出受影响的验收行为。对每项核对证据来源和对象，记录通过、失败、未执行或待确认，并注明后续负责人。

先沿项目规则找到原交付记录、发布手册、测试及验收入口，不另建状态台账。按本次交付目的判断结束条件：源码供件可以在源码层完成；承诺可用业务则还需对应运行与消费者证据。未达到的后续层分别保留，不把业务验收强加为所有源码任务的前置，也不把供件就绪当业务已交付。

| 要证明的事项 | 核对的证据 |
| --- | --- |
| 源码变更通过检查 | 实际变更的版本或差异、适用检查和已读回的结果。 |
| 候选已安装 | 目标环境独立读回的运行版本、受影响配置与必要保留项。 |
| 实际业务行为通过 | 正常入口、实际角色、对象、操作与结果。按影响覆盖必要的拒绝或异常路径。 |
| 业务方已接受 | 有权验收人的确认或项目约定的原始验收记录。 |

证据仍对应当前版本与适用条件时可复用。变化涉及版本、配置、角色或数据时，重验受影响部分。健康检查证明服务可达，业务声明需对应业务证据。模拟验证保留模拟范围。

同一记录累积多轮结果时，给出当前适用的摘要，并标明旧失败或未执行结论的版本及后继证据，保留原始历史。分别核对文件已安装、平台清单可发现、入口实际加载和行为验证；其中任一项不能替代其余项。清单漏列而文件可读时，只按当前证据记录发现缺口，不推断为技能逻辑错误或用文件改动冒充平台恢复。

需要组合安装时，核对供件候选、配套版本、实际安装读回及同对象的受影响消费者。合同、类型、helper、模拟样例、一次HTTP成功或正常退出各有自己的证明范围，不自动证明完整调用链、一般可用性、界面闭环或撤权。已安装但未复验的项，定位原消费者、可行动下一步和结束条件；缺件只影响依赖它的结论。

承诺可用业务时，把目标角色的正常发现入口、清单、同对象办理、结果及返回与所需配置一起核对；后端命令存在或详情直达成功不能证明用户能正常开始。已有证据覆盖的环节直接复用，只补本次缺口，不据此新增全流程重测门。

清理或资源治理分别核对创建与复用、真实结束记录、保护例外、实际退役及物理空间变化。规则已加载、维护运行或只清缓存，各自限定结论；不能代替旧副本退役。来源或结束时间未知时保留原状态，例外注明负责人及下一复核动作；到期只触发复核，不自动授权删除独有数据。经验更新也要区分已写入、实际采用及下一适用批次的效果，重复问题仍出现时检查执行和方法差额，不以文档数量结案。

合并、发布和交接沿项目现有入口执行。发布前确认候选、实际写入范围、回退条件和复验责任方。遇到未知写入结果时先走原读回路径。收尾更新原任务或交付记录，给出已证实结果、剩余缺口和下一可行动节点。
