项目专属业务、技术栈、角色、发布与测试规则从当前项目的 `AGENTS.md` 及其引用的现有文档读取，不从其他项目继承。通用技能不授予额外权限、不替代项目决定；冲突按当前用户指令和适用规则处理，只澄清影响当前动作的未决项，不另建规范或审批。
# 交付核验

先确定本次要证明的结论和适用范围。从需求、实施记录或缺陷回执选出受影响的验收行为。对每项核对证据来源和对象，记录通过、失败、未执行或待确认，并注明后续负责人。

先沿项目规则找到原交付记录、发布手册、测试及验收入口，不另建状态台账。按本次交付目的判断结束条件：源码供件可以在源码层完成；承诺可用业务则还需对应运行与消费者证据。未达到的后续层分别保留，不把业务验收强加为所有源码任务的前置，也不把供件就绪当业务已交付。

| 要证明的事项 | 核对的证据 |
| --- | --- |
| 源码变更通过检查 | 实际变更的版本或差异、适用检查和已读回的结果。 |
| 候选已安装 | 目标环境独立读回的运行版本、受影响配置与必要保留项。 |
| 实际业务行为通过 | 正常入口、实际角色、对象、操作与结果。按影响覆盖必要的拒绝或异常路径。 |
| 业务方已接受 | 有权验收人的确认或项目约定的原始验收记录。 |

证据对应的实际对象、版本、合同及相关条件仍适用时直接复用；只重验真实变化影响的部分，不因交接层级或环境名称变化重跑同一业务。批量创建以真实提交及一次全量完整性/关联/状态/分布核对为依据，后继引用有效结果，不将 apply、assert、回执核验和交接变成多次整包扫描。健康检查只证明服务可达，模拟验证保留其范围；必要实际消费者结果仍须核实。

执行器、传输、回执或校验器自身故障与实际业务数据错误分别报告；只有已观察到错误业务值、关联或漏做效果才据此声明数据/交付问题。校验通过次数和运行时间不代表发现过数据错误，回执存在也不覆盖真实漏写或漏发布。必要事实由负责层核一次，复用原结果，不为“独立核验”递归增加证明文件或重复查询。

同一记录累积多轮结果时，给出当前适用的摘要，并标明旧失败或未执行结论的版本及后继证据，保留原始历史。分别核对文件已安装、平台清单可发现、入口实际加载和行为验证；其中任一项不能替代其余项。清单漏列而文件可读时，只按当前证据记录发现缺口，不推断为技能逻辑错误或用文件改动冒充平台恢复。

需要组合安装时，核对供件候选、配套版本、实际安装读回及同对象的受影响消费者。合同、类型、helper、模拟样例、一次HTTP成功或正常退出各有自己的证明范围，不自动证明完整调用链、一般可用性、界面闭环或撤权。已安装但未复验的项，定位原消费者、可行动下一步和结束条件；缺件只影响依赖它的结论。

核组合安装的“可执行”声明时，沿[真实宿主就绪核验](../implementation-planning/references/host-readiness.md)核本批准确候选的入口准入、分派、stage和必要配置/父对象。文件hash、源码与父数据准备、候选宿主隔离检查、目标环境装载及实际业务结果各有证明范围；未覆盖的层保留未就绪，不从局部READY推导整链可执行。

承诺可用业务时，把目标角色的正常发现入口、清单、同对象办理、结果及返回与所需配置一起核对；后端命令存在或详情直达成功不能证明用户能正常开始。已有证据覆盖的环节直接复用，只补本次缺口，不据此新增全流程重测门。

清理或资源治理分别核对创建与复用、真实结束记录、保护例外、实际退役及物理空间变化。规则已加载、维护运行或只清缓存，各自限定结论；不能代替旧副本退役。来源或结束时间未知时保留原状态，例外注明负责人及下一复核动作；到期只触发复核，不自动授权删除独有数据。经验更新也要区分已写入、实际采用及下一适用批次的效果，重复问题仍出现时检查执行和方法差额，不以文档数量结案。

核验资源退役时，按[资源副本生命周期方法](../project-mgmt/references/resource-lifecycle.md)核本批实际结果。跳过、缓存删除、整目录退役及仍待处理数分别读回；保护性跳过不能计作删除或无剩余。目录分配字节、逻辑大小和卷可用空间差额分别报告，不将压缩、克隆共享块或并发写入影响冒充整目录释放。

核验连续性整改时，先用原记录确认它能发现哪类真实停顿、采取何种动作，以及是否会误催合法长任务、重复写入或扩大等待。上阶段供件或活跃证据不能证明下一阶段已经执行；消息送达、工具调用完成、更新时间和规则安装也不能单独证明推进。核后继时对应当前动作、执行者、来源版本和结果，不只核上一阶段结案。

部分成果只关闭对应对象和阶段，保留完整目标及原恢复节点。预期部分断点须与普通失败、未知写入和整体验收区分；没有精确匹配的实际回执就沿原错误核实，不因状态名称自动重跑或补造成功。方法修订、发布、实际采用及效果分别核验：优先在下一必要业务接续中观察是否发现原问题并推动后继，复用未变证据，不为证明方法而重放已过业务或另建审计流程。

合并、发布和交接沿项目现有入口执行。发布前确认候选、实际写入范围、回退条件和复验责任方。遇到未知写入结果时先走原读回路径。收尾更新原任务或交付记录，给出已证实结果、剩余缺口和下一可行动节点。
