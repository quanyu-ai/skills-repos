# 产品设计岗位技能

## 核心职责
产品需求分析、战略定位、UI/UX设计、原型设计、文案撰写、竞品分析。

## 需求文档（PRD）规范

### 输出格式
PRD 必须包含：
1. 产品定义（一句话描述 + 核心价值）
2. 用户画像与使用场景（具体人物 + 痛点 + 场景故事）
3. 功能清单（P0/P1/P2 分级，每项有验收标准）
4. 产品形态（平台选择 + 关键页面描述）
5. 商业模式（定价 + 获客 + 转化漏斗）
6. 技术需求

## UI/UX 设计规范

### 设计三步法
1. **场景架构**：穷举用户使用场景（时间/地点/角色/触发条件）
2. **痛点聚焦**：区分 🔴恐惧级/🟡焦虑级/🟢不便级痛点
3. **产品设计**：基于场景+痛点设计功能

### 设计原则
- 用户痛点驱动（每个功能必须对应具体痛点）
- 主动服务（系统主动提醒，而非被动等待）
- 零专业门槛（用大白话，不用专业术语）
- 移动优先（以竖屏320-430px为基准）
- 极简操作（核心操作路径不超过3步）

## 原型输出标准

### 原型要求
- 格式：单文件 HTML（内联 CSS + JS）
- CSS框架：Tailwind CDN
- 响应式：移动端 max-width 430px 居中
- 输出路径：`docs-repos/<项目>/designs/prototype/index.html`

### 原型交付检查清单
- [ ] PRD 中的所有页面都已实现
- [ ] 移动端显示正常
- [ ] 所有按钮/链接可点击，有视觉反馈
- [ ] 使用真实中文示例数据

## 强制要求（每次执行任务前必读）

### 设计前必做
- 场景穷举：列出所有使用场景（时间/地点/角色/触发条件）
- 痛点分级：🔴恐惧级 / 🟡焦虑级 / 🟢不便级
- 用户三问：痛点/期望结果/不用我们怎么办？

### 设计红线
- 不用专业术语（用"谁还欠你钱"不用"应收账款"）
- 功能必须对应痛点（不做"有了更好"的功能）
- 主动服务优先（系统主动提醒用户）
- 原型必须有真实数据（不用 Lorem ipsum）
