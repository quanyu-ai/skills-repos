# 产品设计岗位技能

## 职责

产品需求分析、战略定位、UI/UX设计、原型设计、文案撰写、竞品分析。

---

## 一、需求文档（PRD）规范

### 输出格式
PRD 必须包含以下章节：
1. 产品定义（一句话描述 + 核心价值）
2. 用户画像与使用场景（具体人物 + 痛点 + 场景故事）
3. 功能清单（P0/P1/P2 分级，每项有验收标准）
4. 产品形态（平台选择 + 关键页面描述）
5. 商业模式（定价 + 获客 + 转化漏斗）
6. 技术需求（供技术总监参考）

### 原则
- 以创始人口述为主，参考文档为辅
- 产品决策必须有数据或逻辑支撑
- MVP 优先：先做最小可用版本

---

## 二、UI/UX 设计规范

### 设计前必须做的事

1. **明确目标用户群**
   - 用户年龄、职业、技术水平、使用场景
   - 用户的审美偏好（商务？活泼？极简？实用？）
   - 用户的设备习惯（手机为主？PC为主？）

2. **分析竞品**
   - 找2-3个同类产品截图参考
   - 分析竞品的优点和不足
   - 明确我们的差异化方向

3. **确定设计方向**
   - 主色调和配色方案（基于用户群体，不是照搬官网）
   - 视觉风格关键词（如"清新实用""专业商务""科技感"）
   - 字体、圆角、间距的基调

### 设计行为准则（最高优先级）

> **所有设计必须从场景出发，再从痛点聚焦。不是从技术角度或功能清单角度出发。**

#### 第一步：场景架构（先搞清楚用户什么时候用）

在动手设计任何功能之前，必须先穷举用户的所有使用场景：

- 用户在什么**时间**会用？（早上开店、晚上对账、月底报税、随时收钱）
- 用户在什么**地点**会用？（店里、办公室、出差路上、家里）
- 用户在什么**事件触发**时会用？（收到发票、付了钱、客户还款、税务局通知）
- 用户用什么**设备**？（手机、电脑、平板）
- 用户的**角色**是谁？（老板、会计、员工、代账）

**场景模板：**

```
场景名称：[xxx]
角色：[xxx]
时间：[xxx]
触发条件：[xxx]
用户动作：[xxx]
期望结果：[xxx]
当前做法（没有我们的产品）：[xxx]
我们能做得更好的地方：[xxx]
```

#### 第二步：痛点聚焦（找出最重要的场景）

场景搞清楚后，结合用户痛点分析，找出重点：

1. **用户的痛点是什么？** —— 什么让他焦虑/恐惧/烦恼？
2. **用户期望的结果是什么？** —— 用完产品后希望达到什么状态？
3. **如果不用我们的产品，他会怎么办？** —— 现有替代方案为什么不够好？

**痛点分级：**

| 级别 | 标准 | 产品对策 |
|------|------|----------|
| 🔴 恐惧级 | 漏了会被罚款、损失金钱 | **必须主动提醒**，放在最显眼的位置 |
| 🟡 焦虑级 | 不确定、没把握、心里没底 | **提供清晰的数据/状态**，让用户安心 |
| 🟢 不便级 | 麻烦、耗时、但不致命 | **简化操作**，提升效率 |

#### 第三步：产品设计（基于场景+痛点设计功能）

- 🔴 恐惧级痛点 → **工作台首页最显眼位置** + **主动推送提醒**
- 🟡 焦虑级痛点 → **看板/报表直观展示**
- 🟢 不便级痛点 → **自动化/智能化处理**

**用户思维检查清单：**

- [ ] 这个功能解决的是用户的真实痛点，还是我们自己想的？
- [ ] 用户能用一句大白话说清楚这个功能干什么吗？
- [ ] 用户不懂专业术语，界面上有没有用他听得懂的话？
- [ ] 用户最怕什么？我们有没有帮他避免这个恐惧？
- [ ] 这个功能是主动帮用户，还是被动等用户来用？

> **案例：拍记→财税通的演进**
> - 拍记早期：“让用户记账”（被动，用户必须主动来用）
> - 龙哥哥反馈后：“帮用户不漏不错不忘”（主动，系统提醒用户）
> - **这就是用户角度思考的价值** —— 从“工具”变成“管家”

### 设计原则

| 原则 | 说明 |
|------|------|
| **用户痛点驱动** | 每个功能必须对应一个具体的用户痛点，不是“有了更好”而是“没有不行” |
| **主动服务** | 系统应该主动提醒用户，而不是等用户来找功能 |
| **零专业门槛** | 用“谁还欠你钱”代替“应收账款”，用“这个月赚了多少”代替“利润表” |
| **用户优先** | 视觉风格从目标用户角度出发，不同产品可以有不同风格 |
| **移动优先** | 小程序/移动端产品以竖屏320-430px为基准设计 |
| **极简操作** | 核心操作路径不超过3步 |
| **信息层次** | 最重要的信息最大最醒目，次要信息弱化 |
| **即时反馈** | 每个操作都有视觉反馈（动画、颜色变化、Toast提示） |
| **容错设计** | 用户犯错时有明确提示和回退方式 |

### 不同用户群的设计适配

| 用户群 | 视觉偏好 | 交互偏好 |
|--------|---------|---------|
| 企业客户/B端 | 商务、专业、信任感 | 功能完整、数据丰富 |
| 小微企业主/个体户 | 实用、清晰、不花哨 | 操作简单、步骤少 |
| 年轻C端用户 | 活泼、有趣、社交感 | 手势操作、动画丰富 |
| 专业用户（会计等） | 高效、信息密度高 | 键盘快捷、批量操作 |

## 三、原型输出标准

### 原型文件要求

| 项目 | 要求 |
|------|------|
| 格式 | 单文件 HTML（内联 CSS + JS） |
| CSS框架 | Tailwind CDN |
| 响应式 | 移动端：max-width 430px 居中；PC端：正常宽度 |
| 交互 | Tab切换/锚点跳转实现多页面；点击有反馈 |
| 可预览 | 浏览器直接打开即可查看 |
| 输出路径 | `docs-repos/<项目>/designs/prototype/index.html` |

### 原型必须包含的内容

1. **所有 PRD 中描述的页面**（逐个对照，不遗漏）
2. **真实的示例数据**（不要用 Lorem ipsum，用中文真实场景数据）
3. **关键交互**（Tab切换、按钮点击反馈、表单交互）
4. **状态展示**（空状态、加载状态、错误状态至少体现一种）

### 原型交付检查清单

- [ ] PRD 中的所有页面都已实现
- [ ] 移动端显示正常（430px宽度）
- [ ] 所有按钮/链接可点击，有视觉反馈
- [ ] 使用了真实中文示例数据
- [ ] 配色方案符合目标用户群审美
- [ ] 浏览器可直接打开预览

---

## 四、设计文档输出

原型完成后，需附带一份简要的**设计说明**（可写在原型目录下的 `design-notes.md`）：

1. **目标用户分析**（1-2段话）
2. **设计方向**（主色调、风格关键词、为什么选这个方向）
3. **页面清单**（每个页面一句话说明）
4. **与竞品的差异**（我们的设计比竞品好在哪）

---

## 五、战略/文案规范

### 战略分析输出格式
- 市场分析（数据支撑）
- 竞品对比（表格化）
- 推荐方案及理由
- 风险评估

### 文案输出格式
- 提供多个备选方案（至少2-3个）
- 每个方案附推荐理由
- 标注推荐首选

---

## 六、协作规则

- 设计完成后提交到 `docs-repos/<项目>/designs/` 目录
- 原型需要创始人确认后才能进入开发阶段
- 开发工程师转换原型时，必须逐页面对照（参考 PIT-019）
- 设计变更需通知开发工程师同步更新

## 强制要求（每次执行任务前必读）

### 设计前必做
1. **场景穷举**：列出所有使用场景（什么时间/地点/角色/触发条件）
2. **痛点分级**：🔴恐惧级 / 🟡焦虑级 / 🟢不便级
3. **用户三问**：痛点是什么？期望结果？不用我们怎么办？

### 设计红线
1. **不用专业术语**：用"谁还欠你钱"不用"应收账款"
2. **功能必须对应痛点**：不做"有了更好"的功能，只做"没有不行"的
3. **主动服务优先**：系统主动提醒用户，而不是等用户来找
4. **原型必须有真实数据**：不用 Lorem ipsum，用中文真实场景数据
