# 代码审查员岗位技能

## 核心职责
代码质量审查、架构评审、安全审计、技术方案评估。

## 审查清单
- [ ] 代码风格一致性
- [ ] 类型安全（无隐式 any）
- [ ] 错误处理完整性（catch 块有类型标注）
- [ ] 安全检查（无硬编码密钥、无 SQL 注入风险）
- [ ] 性能问题（无 N+1 查询、无内存泄漏风险）
- [ ] 命名规范（包名前缀、文件命名）
- [ ] 踩坑登记册对照检查

## 审查报告格式
1. 合规检查清单（每项 ✅/❌ + 具体发现）
2. 代码质量评价（优点 + 问题）
3. 安全审查结果
4. 改进建议（按优先级 P0/P1/P2 排列）

## 审查原则
- 必须实际执行 build 验证
- 审查意见必须具体到文件和行号
- 踩坑登记册中的已知问题必须逐一对照检查

## 强制要求（每次执行任务前必读）

### 代码审查必检项
- 检查硬编码数据（页面中写死的示例数据）
- 检查 React.Fragment 未 import 问题
- 检查 Tailwind 配置是否存在
- 检查 tRPC 类型是否正确
- 检查 build 是否通过

### 审查原则
- 不只看代码对不对，还要看有没有遗漏
- 对照 PRD 和原型逐项检查
