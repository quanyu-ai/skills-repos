# 资源副本创建、关闭与退役

用于项目已有工作树、发布副本和构建产物的清理及空间压力处理。先读当前项目的创建器、清理器、原交付记录和授权范围；本方法不授予删除权限，不规定跨项目统一目录、保留时长、空间阈值或回退数量。复用原工具、锁、记录和负责人，不新建台账、审批或常驻扫描器。

## 从创建与关闭减少积累

创建前复用适合当前完整任务的已有副本；仅因实际并发写冲突、基线不兼容或必要隔离另建。不得让两个写入者共用脏工作树；同一目的的重复构建先核已保存候选与结果。

创建者在原记录保留目的、来源及实际消费者；结束时记录真实结束或替代关系，交给项目指定的退役执行者。源码合并、会话空闲、目录年龄不等于消费者已结束。历史证据引用与运行时路径依赖分别判断：证据可保留，不因历史引用永久保留全部可重建目录；真实路径消费者仍需保护。

发布收尾同时接续受影响回退组合的兼容证明及其适用代际，不把缺证明留到下一次磁盘告急才处理。发布改变 schema、工具链、配置或身份绑定时，核受影响回退组合的兼容证明是否仍适用。不能把过时证明造成的“未识别”当作没有历史回退版本；也不能为释放空间删保护、伪造兼容或为造证明重复部署。仅核变化涉及的恢复能力，未变证据复用。

## 把可恢复关闭接到退役

开发工作树与运行副本分别收口。有远端代码库的任务，核精确提交已推送或对应 PR 已合并；squash 合并沿原 head/差异等价证据，不只看祖先关系。本地存在 SHA 不等于远端已有备份；临时可重建夹具也不必为清理另造 PR。数据库、凭据和业务材料不随源码推送。

源码与必要恢复引用已保存、当前消费者已释放且没有独有改动的副本，在原批次收尾就交原入口退役，不等整个模块或 Owner 总体验收。把必须保留的少量运行输入、回执和原字节按原机制留在副本外，再回收完整可重建目录；不能因历史证据引用长期留下所有依赖、缓存和历史安装包。源码远端就绪也不代替现役、在途、实际回退和独有材料检查。

保留例外对应具体消费者、当前原因、原负责人和下一释放节点，写在原记录；一个未知目录不阻其他成熟目标。已关闭且证明可退役的目标按原授权继续分批，不为每个目录重批。当前批次未选中只表示未处理，不能当成无授权、不可回收或全部已处理。已采用的保留期限与例外沿项目实际配置执行，不能由本技能统一缩短或凭年龄解保护。

## 分批落实实际退役

先区分现役/在途/回退依赖、可重建副本、缓存与唯一材料，再选一批收益明确且证据成熟的目标。存在独有数据库、未提交修改、未知忽略文件或秘密风险时，只核非秘密元数据与原负责人处置，不为清理读取内容或当作缓存删除。

对普通已跟踪证据，核精确 Git 对象可恢复性及实际文件差异；单凭扩展名或“被跟踪”均不够。项目支持将必要材料按原入口保留到副本外时，可保留原字节与来源再释放可重建主体；不能借搬运扩大授权或把复制材料量计作释放量。

删除前在原串行入口复核目标身份、根边界、符号链接及反向消费者、运行/排队/回退引用和独有材料。无打开文件只是其中一项证据。锁忙时等原事务自然安全点，不强杀、不抢锁、不另起物理写入者。有限批次的逐目标重核与实际删除对象相符；共享活跃引用、反向依赖及状态一致性校验仍保留。发现每次只删少量却反复重核全部历史来源、维护连续占锁挡住已排安装时，由原入口改进批次范围和安全点接续，不靠省略删除前校验或中断事务提速。部分目标未知只保护该部分，其他成熟目标继续；不能以整模块尚未验收为由长期占用已可独立释放的资源。

用项目支持的关闭/工作树移除/回收入口处理明确目标；保留必要分支或精确提交恢复引用及副本外原回执，不顺带删除分支、清全部 WIP、重置或裁剪对象库。先完成有限批次并读回，再决定后继，避免未受限扫描或反复补丁发布。

## 发现清理未有效执行

空间紧张时先读卷可用空间与原清理摘要，按需要检查有限候选。逻辑大小、分配字节、卷空间差额不同；APFS 克隆、压缩和并发写入会影响差额，不用样本乘目录数承诺释放量。容量先核原执行入口真正消费的配置、配置优先级、当前候选预算及实际文件系统事实；文档缺省值、旧决策和辅助脚本自加阈值不能冒充生效门槛。逐项保留原余量、物理容量及其他预算约束，不能为了通过而降低配置或借用别的候选单次决策。仅错误口径造成等待时纠正口径，按原入口接续，不等无关清理全部完成。

创建/安装的空间预算应考虑本项目实际临时峰值和运行余量；不能仅凭小的固定预估声称足够，也不凭通用方法猜阈值或无限提高保留预算。

沿原巡检核以下信号并采取有结果的动作：

| 信号 | 核查与接续 |
| --- | --- |
| 维护返回成功但旧副本未减少、空间仍紧 | 分清已运行、整目录删除、缓存删除、跳过及未处理；检查真正卡点，不以进程健康结案 |
| 候选全跳过或达到批次上限 | 保留真实未处理数及跳过原因，由原入口有限复核；不写成已删除/无剩余，也不无间隔自旋 |
| 大批共同缺证明或普通材料被逐文件卡住 | 按共同原因补来源、结束、兼容或保留证明；逐项保留真实例外，不用大量微补丁或后缀白名单绕过 |
| 保护例外长期未变化 | 核原负责人是否执行精确下一动作、证明是否已被后继补齐；不反复查同一缺失日志，不凭到期自动解保护 |
| 清理入口长期 BUSY、失败或根本未触发 | 核原锁/执行者/下一安全点、最近实际执行及错误；只处理真实停顿，不将合法长事务判死、不另建 writer |
| 维护本身不断积累大计划文件或重复扫描 | 复用有效摘要与未变证据，沿原机制限定详细产物和扫描范围；保留必要恢复记录，不能为节省检查而漏掉到期或新增风险 |

定时入口的触发与去重必须允许时间到期、消费者释放及修复后的必要重核；同样输入不重复催办，不等于永远不再核结果。没有新线索时保留精确阻塞，变化时回到原节点；可行动保护例外长期无人处理或空间持续恶化需按原通知规则报告，不能安静标健康。不要声称技能文本本身已经实现定时触发或运行故障检测。

## 收尾及效果复核

在原记录分别写本批真实整目录退役、缓存/压缩等其他动作、跳过和剩余保护，以及卷空间前后读回和测量限制。删除回执不能替代删除后目标不存在及必要现役/回退引用未损坏的有限读回；复用已有健康与业务证据，不因清理重跑无关业务。

未解决项保留原负责人、具体缺件与下一可行动节点。下一必要创建/关闭/巡检中核是否减少新的无主副本、成熟目标能否实际退役，有无误删风险或额外负担；方法已写入、已发布、已加载、实际采用与效果分别核实。不要为了证明采用额外开会、回执、测试或建账。

独立准备与环境变更的不同准入条件，沿[真实宿主就绪核验](../../implementation-planning/references/host-readiness.md)判断；不把清理策略或辅助脚本中的额外断言升级为所有阶段的通用前置。
