# 任务连续性检查方法

用于已有授权任务的定时巡检和接续。先核项目原规则、交付记录、发布与测试入口；不把本参考变成自动派单授权或要求所有项目采用同一工具。

## 从目标与当前动作发现问题

先对照完整授权目标与本次选中子集，再核每项未完目标的当前阶段、原负责人、必要输入、实际资源冲突及下一可行动节点。源码准备、安装、消费者验证和接受分别判断；一个提供方未完成只阻挡依赖它的动作。核引用的输入是否已被后继版本补齐，避免沿历史状态等待；只有来源、版本和适用条件仍匹配，旧证据才能支持当前结论。

优先查这些具体信号，不为覆盖率制造检查或新工作：

| 信号 | 有限核实 | 接续方式 |
| --- | --- | --- |
| 必要输入已齐、负责人空闲，但动作未开始 | 原记录及一次紧凑状态，排除真实暂停、在途事务和工具拒绝 | 已有授权内向原负责人一次给出精确动作与结束条件，确认实际动作后再核结果 |
| 上阶段已供件或已结束，下阶段无人接 | 原消费者是否接到可用版本、配置、入口及对象 | 明确下一动作执行者；上一阶段活跃标记不能结转到新阶段 |
| 笼统等公共服务、环境或整体模块 | 必需的具体接口、配置、对象与真实冲突；核是否误用历史执行子集 | 仅挂必要依赖，独立准备及成熟对象继续；不凭缺证据删掉安全前置 |
| 已安装未验证，或修复反复发布仍无业务结果 | 当前实际运行版本、原测试入口、同对象结果及失败是否被原负责人接续 | 只补受影响验证；复用已过部分，完整业务配套合批，避免逐叶补装 |
| 声称活跃或已派发，却无对应接续事实 | 证据是否属于当前动作、执行者和阶段；是实际产物/游标推进还是只查状态 | 进展未观察先只读核实，不能凭活跃标签判健康，也不能直接重复派单 |

## 防止误催和循环

合法长任务、工具等待或真实资源占用可能暂时没有新输出；结合原运行节点和有限只读状态判断，不要求每轮新增产物、写业务或发回执，不固定超时强杀、释放在途锁或另起执行者。单纯命令完成、更新时间、消息送达和协调记录自引用不是进展证据。

派发去重与结果复核分开：相同输入不重复催办，但仍核原负责人是否实际接续；新证据证明已转阶段、已失效等待或持续失败时，按新事实处理原节点，不逐级转发同一阻塞。未知写入先核原事务与源键，不重放成功上游；实际权限拒绝或工具拒绝不由调度代绕过。

原流程支持部分断点时，按其明确回执、原执行身份及实际对象读回分类，保留整目标未完和同一执行链的恢复动作。不能以通用失败名自动重试，也不能以少量成果关闭全目标。执行前仍按项目原入口核必要条件，不能从本参考推导新身份、权限或执行模式。

## 验证方法有效并回灌

在原交付记录中保留已发现问题、原因依据、原负责人、处理及接续结果，未知不写成已证实。下一必要任务中核问题是否再次出现、是否推进到下一实际成果，以及有无误催、重复执行或新增等待；不编节省比例，不另造业务作效果测试。仅将有依据且可复用的方法补入现有技能；项目对象、角色、环境和执行参数留项目原来源。定期归并、修订或撤销无效要求，技能更新和通知本身不算整改闭环。没有真实异常、必要检查已经覆盖或负责人有效执行时，沿原机制安静结束。
