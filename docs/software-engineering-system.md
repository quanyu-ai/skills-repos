# 自建软件工程方法：用户结果与必要检查

自建规范、技能、模板和插件的第一目标是：用户看得懂、能够用、业务信息清晰、能够解决问题。设计、开发、测试和交付围绕同一个原用户任务；供件、类型、接线、局部PASS、安装和报告只是手段，不能替代任务完成。

## 具体怎样判断

- 设计从角色要判断或完成的事情出发，明确对象、范围、期间、状态、必要依据和下一步。总览先回答状况与关注事项，目录负责发现入口，办理须给足决定/执行所需信息；不能靠组件、入口或说明凑功能。
- 真实来源不支持主要判断时补齐必要业务能力。当前页不冒总量，不同范围不拼分母，有记录不冒已完成；加载、已确认空、无权及失败应可区分。可选信息不阻合法操作，真正必要的缺项只挡依赖它的动作。
- 开发贯通原任务需要的实际producer、consumer和工作模式。测试形状来自真实提供方，不能伪添API/字段、另造正确context或替换正在验证的入口；原错误、并发和未知写入恢复保留。
- 预期来自原需求和业务事实，不能让代码、原型和测试互相自证。实际观察用户能读懂状态、完成动作、核对或找回结果。错误提示正确或另一视图通过不代正常用户任务；核心用途缺失直接判未完成并继续修复。
- 按真实变化和风险选最少必要检查。小改只看受影响保证，未变结果复用；不固定全矩阵、审阅人数量、截图配对、Owner重复确认或逐层报告。只有真正的业务决定、权限/生产/不可逆边界才追加相应处理。

## 减少阻塞和消耗

一次解决当前用户任务，避免按文件、技术层或证明包循环交接。原负责人有效执行不重派；不按时长或百分比推断超时失败。无需固定外部台账、模板齐备、特定CLI/OS、全局doctor或无关样本才可开始。

检查必须能发现本次真实问题并改变下一动作；没有这种作用就删除或收窄，不增加替代检查器。保真实身份、权限、租户、数据正确性、事务和未知写入保护；不能以减法名义吞错、越权或重放成功效果。已确认的授权不重复申请。

## 唯一来源与采用

本仓库已合并版本是共享方法的唯一编辑源，项目只维护自己的业务合同和结果，不复制通用技能正文。官方安装缓存是当前分发，不在缓存另改规则；旧版本/兼容副本移出读取与发现路径，需保留的历史压缩封存。

按实际需要选技能，不串行调用全套。已有原记录足够就直接更新，不建立新规范库、采用报告或证据台账。方法升级应检查会改变的判断和实际入口；文本或格式检查不能证明产品已经可用，也不要求为推广方法重跑已过业务。
