# 自建软件开发工程技能体系指引

本指引适用于使用本技能库的各项目。共享标准、通用技能、模板、可复用案例与适配参考以 [skills-repos](https://github.com/quanyu-ai/skills-repos) 已合并版本为准。项目固定采用的提交或发布版本，在现有项目记录中登记。产品需求、项目决定、角色数据、运行记录和验收证据由各项目维护。

## 组成和职责

| 资产 | 在流程中的职责 | 维护位置 |
| --- | --- | --- |
| 规范 | 定义通用交接、验收、证据与变更要求。业务规则及其批准范围由项目明确 | 本指引与项目采用的规范 |
| 技能 | 告诉执行者何时介入、怎样做、如何判断完成。引用规范及必要资料 | 各技能的 `SKILL.md` |
| 模板 | 承载交付所需字段。已有项目记录可以直接承载同样信息 | 对应技能的 `templates/` 或项目原记录 |
| 案例 | 给出输入、期望、观察结果与适用边界。可复现问题可成为回归案例 | 项目案例保留在项目内。脱敏后可复用的案例放在对应技能的参考资料 |
| 执行参考 | 说明如何在指定工具或环境中操作、取证和验证 | 对应技能的 `references/` 或项目手册 |
| Hook | 在明确的交接事件运行检查或发出提示，例如核对评审与候选版本 | 采用方的项目或插件适配。业务判断沿用技能和规范 |

规范与项目决定共同确定执行范围。技能、模板、案例和 Hook 中的默认值不能替代项目决定。通用技能以工作产物和验收行为为输入输出。运行环境专用路径、事件和依赖放在适配层。角色技能分配职责，工作模式安排协作，二者可按项目组合。

## 从需求到交付

1. **立项和需求。**沿用项目原始业务记录，明确目标、范围、角色、对象和可观察的验收行为。对影响后续步骤的待决事项写明责任方及受影响范围。
2. **方案和原型。**方案记录关键取舍、接口、状态、权限和失败行为。实质交互变更形成可走通的原型，并在交给开发前运行 [原型评审](../prototype-review/SKILL.md)。评审记录要对应当前原型版本，说明实际走过的路径、阻塞问题、复验和剩余事项。可用 [最小交接记录](../prototype-review/templates/handoff.md)，也可复用已有记录。
3. **实施和代码评审。**用 [实施计划](../implementation-planning/SKILL.md) 将确定的结果拆成可独立验证的切片。发生异常时做 [系统排错](../engineering-debugging/SKILL.md)，关键行为用 [回归测试](../regression-testing/SKILL.md) 固化。按影响评审需求、工程质量和回归证据。
4. **交付和反馈。**按 [交付核验](../delivery-verification/SKILL.md) 分别记录源码验证、安装读回、实际业务和有权验收人的确认。失败或未运行的路径保留下一节点。仅影响局部画面且不改变行为、权限、状态或语义的改动，检查受影响画面即可。

使用 [交接 Hook 参考](../prototype-review/references/hook-integration.md) 时，从交接事件运行确定性检查，先以提示模式验证匹配、缺失、过期和轻量场景。各项目可以在同一交接入口直接执行评审和检查。

## 迭代与发布

1. **保留触发证据。**在项目原记录写清当前技能版本、输入、期望、观察结果和复现方式。单次项目配置差异留在项目内。有可复现的通用缺口再回共享库。
2. **改到对应层。**业务语义与授权由项目原负责人更新决定。通用要求有误改规范，执行步骤漏项改技能，证据缺字段改模板，判断样例不清补案例，运行方式变动改执行参考或 Hook。关联文件引用同一来源。
3. **验证修改。**先检查相关入口、链接和兼容性。行为变化用原案例及正常对照验证。涉及 Hook 另验触发范围、缺证据、过期和轻量路径。小改动做相称检查。记录运行环境和观察结果，区分源码检查、平台加载和实际执行。
4. **通过 GitHub 维护。**一个可审查变更使用一条分支和一份 PR，写明问题、受影响资产、兼容性、证据和采用方式。按仓库权限评审和合并。Git 提交用于追溯内容，共享采用可按团队需要使用发布标签。影响既有项目的格式或执行契约时说明迁移和退回上一个可用版本的办法。
5. **核实项目采用。**采用项目记录版本及启用范围，确认平台发现并实际调用变更入口，用一个受影响场景复验。留在项目的验证证据可以通过引用指向共享版本。若未加载、未运行或仅有模拟结果，记录对应状态。

## 项目试跑的最小对照

一次试跑从同一需求走到同一版本的交接记录，覆盖主流程、一个关键异常或拒绝，以及一个轻量改动。评审发现的问题按原路径修订复验。提示型 Hook 应分别识别当前评审、缺失评审、旧版评审，并对轻量改动给出相称提示。试跑记录区分技能发现、实际操作、模拟范围和未验证事项。
