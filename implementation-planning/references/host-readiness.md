# 组合安装的真实宿主就绪核验

用于已有宿主、插件、执行包或配方组合发布，尤其是入口、版本、stage、上下文或配置变化。沿当前项目原准备包、测试和安装入口执行，不新建就绪平台、登记册、审批或通用runner。源码合并不以共享环境已安装为前置；业务安装前应收齐该可用切片的必要接线，独立成熟切片继续。

## 核准确候选，而不只核文件齐全

先对照原授权的本批剩余结果与当前选中子集，列明真实负责人与尚缺依赖。只核本批受影响调用链，不因一次漏检重开已过全模块。

从用户或受管任务实际启动的入口，追到准入解析、子执行入口或分派器、注册的stage/handler、真实factory/callback、提供方与消费者，以及必要配置、schema/生成客户端、身份范围、父对象和恢复/读回契约。宿主能解析请求不证明下游stage接受同一上下文，类型或导出存在也不证明实际注册和调用。

核输入携带的准确包、profile、接口及上下文版本与每个实际消费点的接受合同。不同组件可以合法使用不同版本；检查约定的兼容组合，不要求全链版本字符串相同，不用“同一最新版”代替组合证明。升级生产者时同时查宿主准入和下游消费者，不能只更新枚举、清单或文件pin。

文件指纹匹配证明选中了哪些字节，不证明其行为相容。候选冻结后复用同源证据；相关入口、版本、配置或返回形状又变化时，只补对应接缝，不能将旧候选通过结论移到新候选。

## 核实际配置与当前阶段的约束

候选准备时核原入口实际读取的策略文件、配置优先级和有效值，并绑定当前候选及实际测量。缺省值只在配置缺失时适用；旧文档、别的候选决策或临时 wrapper 硬编码不能代替当前生效配置。有效值满足与否由原入口及其全部预算约束判定，不擅改阈值，也不因误读制造额外等待。

物化、隔离客户端或源码准备与停止服务、共享数据库迁移、实际业务写入分别判断真实冲突。只要求本阶段原入口必需的条件；辅助脚本自加的“整个场景必须为空”等断言须有实际依据，不能冒充原入口拒绝。过时 PREPARING 或未释放引用先核真实执行和未知写入，再由原 finish/stop/release 等正常入口收尾；不直接清状态、不擅恢复别的任务。相关写阶段尚待安全点时，其他原入口允许的独立准备继续。

## 用真实装配逻辑做有限验证

安装前优先在准确候选上用既有隔离夹具或已有无写检查运行真实入口解析、guard和分派/stage逻辑，使用与本批合同相符的非秘密输入。I/O可显式模拟；正被验证的准入、身份/版本判定、响应guard和stage分派不能替换为无条件允许，也不能手工补齐真实宿主本应提供的参数。保留实际输入来源与替身范围。 上下文或跨进程合同改变时，由实际生产构造函数生成输入并经过真实wire形状；夹具不能补真实接口不存在的字段来使组合通过。

按变化选择最少合法正向及必要错误版本、配置缺失、返回形状和拒绝路径，覆盖所有受影响入口族；共用未变接缝复用。正向要证明准确请求被真实消费者接收并得到约定结果；不能只比正则文本、方法存在、文件数量或成功退出。修复先保留能复现漏接的失败，再验证正确调用及拒绝边界，不削弱权限、事务完整性或恢复约束。

涉及摘要、JSON/JSONB或其他持久编码时，让受影响数据按真实序列化和存储语义往返；核清摘要按原文字字节还是语义计算，不能用保持对象插入序的clone替代会重排对象键的存储。

重排事务或批处理时，定向验证真实调用与返回合同、外部读取顺序/时间消耗及最终一致性检查；不以虚拟时间模型冒真实吞吐。隔离宿主链通过仍不是目标环境和业务通过。

调用会启动worker、修改数据库或执行业务时，不把它伪装成只读预检。优先复用既有可无写消费的解析路径或隔离I/O；没有安全无写入口时，明确未验证边界，交项目原执行者在授权安装后的第一个必要动作核验，不随意新增dry-run模式、身份、权限或环境。不把未知边界称为整链READY。

## 一次收配套，按原入口安装与收口

在原准备记录对本批所有受影响切片一次核已知缺件、唯一提供方和可消费版本。版本准入、stage注册、正常宿主上下文、必要初始化/配置与实际消费者随同一可用切片交接；不为每个helper或失败截图拆新安装，也不为等待无关未成熟模块扣住成熟批次。紧急必要修复可有限发布，说明目的及受影响验证。

准备摘要分别给出源码/父数据检查、候选真实宿主链检查及其替身范围、目标环境装载/实际准入、业务提交与独立读回/消费者验证。缺哪项就保留哪一层未完成，不从“源与父数据就绪”推导“能够启动”。有权验收人的接受仍单独保留。

由项目原发布执行者在真实安全点安装完整候选，读回目标版本及受影响配置，再用正常入口完成实际数据或业务结果与必要拒绝。未知写入先按原对象/键对账，已成功部分不重放；安装失败回退只是止损，不能代替业务交付。原测试负责人拿到准确运行版本、对象和窗口后，只补受影响验证。

新发现缺件先判断是本批已知合同未覆盖、运行条件变化还是测试替身掩盖；由原层修复并检查同类受影响接缝，不无边界排查全站。将修订及下一实际批次效果写回原交付/测试记录，检查是否减少同类漏检、碎片安装或新增无效等待；不以技能更新、消息送达或安装次数证明改进有效。
