项目专属业务、技术栈、角色、发布与测试规则从当前项目的 `AGENTS.md` 及其引用的现有文档读取，不从其他项目继承。通用技能不授予额外权限、不替代项目决定；冲突按当前用户指令和适用规则处理，只澄清影响当前动作的未决项，不另建规范或审批。
# 实施计划

从项目已有需求、设计和当前源码入手。在原任务或交付记录中写明目标、范围、验收和基线。只对会改变行为或授权边界的待定事项说明可选做法、取舍和受影响步骤。已有决定直接引用。涉及实质交互变更时，核对 `prototype-review` 对应本次交接原型版本的结果，只将未解决且影响实施的问题标在相关切片上。文案或样式等局部修改只需写明变更和检查。

从项目规则进入原需求、方案、实施交接与验证记录，不另建计划台账。先用当前决定和实际回执核对旧计划：目标、当次授权、设计准备、源码供件、安装及业务验证各自是什么状态；历史“未授权”或“待安装”不覆盖后续决定，已通过工作不因计划刷新重开。

1. 按可独立验证的业务结果拆分。让实现、依赖和验证落在同一切片。只有两部分可以分别实现、检查和交接时才拆开。
2. 每个切片写清责任方、需求或方案引用、输入和输出、依赖及执行顺序。核过现有代码后列出实际入口、拟改路径和测试位置。尚无代码时先写接口或状态和可观察结果。
3. 将主要失败模式分配到能检验它的切片。权限、金额、状态和重试等影响较大的行为，写出具体允许、拒绝或失败后的可见结果。涉及上线时，记录兼容性、数据与回退前提，交项目指定的发布负责人。
4. 可并行的切片明确各自写入范围和接口交接。共享文件、环境或数据存在真实写入冲突时，明确先后顺序和释放条件。独立切片继续推进。

有用户界面的可用流程，应从目标角色的正常入口串到清单、详情、合法操作、审批或后续处理、结果和返回；只选本次确有的环节。已有详情或命令不证明入口、清单和角色可见性已接通。安装前在原记录逐项对应真实宿主调用、提供方与消费者、配置及必要初始化；有缺口就给精确接口和原负责人，不以估计供件或手工补齐的测试输入宣称完整。

任务创建工作树、候选或临时产物时，沿已有记录绑定用途、负责人、可重建来源和真实结束条件。交给后继不等于已结束；被替代、失败或放弃时记录实际处置，运行中、回退依赖及独有数据的保护另列。收尾按可用流程或资源退役的实际结果判断，不用“策略已设置”代替效果。

依赖以真实接口或供件回执为依据，注明待制作、已供件与已接通的差别；不要将估计的文件数量或旧环境候选写成成熟交付。需要组合发布时，把提供方、消费者及实际宿主调用、配置/初始化和兼容版本纳入同一可用结果，按项目职责交接；不强求每项都有初始化。在已确认范围及适用设计确认内，源码准备不等无关模块或最终业务验收，不跳过必要的设计确认。每段完成后指向下一可行动节点和结束条件，不能停在“等待公共服务”或“已交给发布”。

交接前逐项核对是否覆盖已确认需求，每个切片是否能说明由谁做、做到什么以及怎样证明。实施发现原计划有误时更新受影响的步骤与验收。
